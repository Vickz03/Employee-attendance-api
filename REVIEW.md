# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / line 73 | Returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | Calling `GET /health` when MongoDB server is stopped still returns HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` wrapped in a try/except block returning HTTP 503 on failure. |
| 2 | `create_employee` / line 79 | Check-then-insert pattern (`find_one` followed by `insert_one`) with no unique index or `DuplicateKeyError` handling. | Two concurrent `POST /employees` requests with identical `emp_code` both pass the check and attempt inserts. | Created a unique index on `emp_code` at startup and handled `pymongo.errors.DuplicateKeyError` to return HTTP 409. |
| 3 | `EmployeeIn` model / line 53 | Allowed identical `shift_start` and `shift_end`, violating the contract requirement that `shift_start != shift_end`. | `POST /employees` with `shift_start="09:30"` and `shift_end="09:30"` returns 201 instead of 422. | Added a Pydantic field validator rejecting requests where `shift_start == shift_end`. |
| 4 | `create_employee` / line 82 | Stored `datetime.now()` (local naive time) and returned datetime object directly instead of epoch milliseconds. | `created_at` in the JSON response was not an integer epoch millisecond count, failing the OpenAPI schema. | Replaced with `datetime.now(timezone.utc)` truncated to seconds and serialized to epoch ms via `instant_to_epoch_ms`. |
| 5 | `list_employees` / line 93 | Incorrect pagination offset calculation `skip = page * page_size`, which skips page 1 records completely. | Requesting `page=1&page_size=20` skipped the first 20 employees; page 1 showed page 2 data. | Fixed formula to `skip = (page - 1) * page_size`. |
| 6 | `list_employees` / line 94 | Total count was computed across the entire collection (`db.employees.count_documents({})`), ignoring the department filter. | Filtering by `department="Engineering"` returned a subset of employees but `total` reported the unfiltered count. | Changed to `db.employees.count_documents(q)` using the active query filter. |
| 7 | `list_employees` / line 95 | Missing sorting by `emp_code` ascending as required by OpenAPI contract. | Response order was non-deterministic depending on natural MongoDB storage order. | Added `.sort("emp_code", ASCENDING)` to the query cursor. |
| 8 | `compute_late_minutes` / line 33 | Performed naive datetime math against `punch_in.replace()`, ignoring IST timezone alignment and whole-second truncation. | For a shift at 09:30 IST, a punch-in from UTC was compared directly to naive local hours, computing inaccurate late minutes. | Aligned calculations strictly in IST (`UTC+05:30`), truncating instants to whole seconds, enforcing the 10-minute grace period (> 600s). |
| 9 | `compute_work_hours` / line 40 | Used Python's built-in `round()`, which applies Banker's Rounding (round-half-to-even) rather than the required half-up rounding (R4). | Intermediate values like `4.525` rounded down to `4.52` instead of rounding up to `4.53`. | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 10 | `compute_overtime` / line 44 | Assumed shift end was on the same calendar day; failed for overnight shifts (`shift_end <= shift_start`) and omitted the 30-minute threshold. | Overnight shift ending at 06:00 IST computed negative or invalid overtime; punch-outs with 15 min overtime returned 15 instead of 0. | Added overnight calendar day adjustment (+1 day) and strictly enforced the >= 30-minute minimum overtime rule. |
| 11 | `punch_in` / line 102 | Used local datetime `ts.date().isoformat()` rather than IST calendar date with R1 overnight shift assignment. | Punch-in at 05:00 IST for a 22:00-06:00 shift was assigned to the punch day instead of the previous shift start day. | Implemented `derive_attendance_date` applying IST conversion and overnight shift rule R1. |
| 12 | `punch_in` / line 104 | Check-then-insert race condition on `find_one` then `insert_one` without unique index on `(emp_code, date)`. | Concurrent punch-in requests created duplicate records for the same employee and date. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 13 | `punch_in` / line 101 | Did not handle non-existent employee; accessing `emp["shift_start"]` raised an unhandled `TypeError` (HTTP 500). | `POST /attendance/punch-in` for an unknown `emp_code` crashed with 500 instead of returning HTTP 404. | Added explicit check for employee existence, returning HTTP 404 when not found. |
| 14 | `punch_in` / line 119 | Injected internal `doc["id"] = str(res.inserted_id)`, violating the OpenAPI schema which has no `id` field. | JSON response contained an unexpected `"id"` key and raw BSON datetime objects. | Removed `id` injection and serialized all fields according to `AttendanceRecord` schema with epoch milliseconds. |
| 15 | `list_attendance` / line 144 | Loaded the entire collection into memory (`list(db.attendance_logs.find(q))`) before sorting and slicing in Python. | Severe memory and latency degradation on 100,000 records; potential OOM crash. | Moved filtering, sorting (`date` DESC, `emp_code` ASC), and pagination (`skip`/`limit`) into MongoDB queries backed by indexes. |
| 16 | `list_attendance` / line 136 | Did not validate `date_from > date_to`, accepting logically inverted date ranges. | `GET /attendance?date_from=2026-07-20&date_to=2026-07-10` executed an impossible query without validation. | Added validation raising HTTP 422 when `date_from > date_to`. |

Also note anything you looked at and decided was **not** a defect, and why:
- **`date_from` and `date_to` string comparisons in MongoDB**: In MongoDB, ISO 8601 string dates formatted as `YYYY-MM-DD` have strict lexicographical ordering matching chronological date ordering. Querying with `$gte` and `$lte` on string dates in indexed fields is fully correct, performant, and preserves the schema defined in `DATA_MODEL.md`.
